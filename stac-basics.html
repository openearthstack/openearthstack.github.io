STAC Specification Basics.

STAC is the open specification every modern Earth observation stack uses to describe and search spatial assets.

What it is

STAC (SpatioTemporal Asset Catalog) is a lightweight JSON-based specification for describing geospatial data. It defines a common shape for metadata so different archives, processors, and tools interoperate without per-provider adapters.

Core objects

Item
A single asset with spatial, temporal, and provenance metadata. One Item per scene is typical.
Collection
A group of related Items sharing the same schema (for example, all Sentinel-1 IW GRD scenes).
Catalog
A container that can hold Collections and sub-Catalogs. Usually the top-level entry point.

Extensions

STAC's core is intentionally minimal. Domain-specific metadata lives in extensions: sar (polarisation, frequency band), sat (orbit state), view (incidence angle), proj (CRS), eo (cloud cover for optical). Teams can add private extensions for internal metadata.

STAC API

A RESTful API spec built on top of OGC API - Features. Endpoints include /collections, /search, and /items/{id}. Most major EO platforms expose a STAC API: Microsoft Planetary Computer, Element 84's Earth Search, USGS Landsat, NASA CMR, CDSE.

Why it matters

Write your pipeline once against STAC. Swap data sources without touching business logic. Archive your own outputs as STAC Items so the next team, or the next model, can consume them directly.
